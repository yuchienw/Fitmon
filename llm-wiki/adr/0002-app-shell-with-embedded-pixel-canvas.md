# ADR-0002: 從全螢幕遊戲引擎轉向「現代 App 外殼 ＋ 局部嵌入像素畫布」架構

- **狀態**：已批准 (Approved)
- **決策者**：產品團隊、全端架構師 & 使用者 (User Alignment)
- **日期**：2026-11-01

---

## 1. 背景與決策脈絡 (Context & Trigger)

原先架構規劃將整款應用設計為「全螢幕 PixiJS 2D 像素遊戲引擎（180×320 虛擬低解析度畫布覆蓋整個 Viewport）」，所有頁面、選單與互動皆以遊戲視角呈現。

然而在深入規劃與使用者反饋評估後，團隊發現：
1. **使用者操作心智 (User Mental Model)**：全球手機使用者對健身與習慣類軟體（如 Duolingo、Strava、Forest）的預期是「**標準手機應用程式介面**」——底部固定導覽列（Bottom Navigation Bar）、頂部標題與返回鍵（Top Header）、平滑的長列表滾動與標準表單輸入。
2. **全端開發者人體工學 (Developer Ergonomics)**：若整款 App 都在 Canvas 遊戲引擎中運作，表單文字輸入、繁中字型渲染、長動態列表平滑滾動、鍵盤避讓等 Web DOM 天然具備的優勢，皆需在 Canvas 中以低階座標計算硬刻，大幅拉高研發門檻與技術債。
3. **設備功耗與發燙 (Battery & Performance)**：全螢幕遊戲引擎需維持 60FPS Render Loop，在手機端容易發燙與劇烈耗電。

---

## 2. 決策方案 (Decision)

決定將系統整體架構調整為 **「現代 App 外殼 (App Shell) ＋ 局部嵌入像素畫布 (Embedded Pixel Canvas Widget)」**：

```
+-------------------------------------------------------------+
| 📱 上方頂部導覽列 (Top Header)                               |
| [◀ 返回] (二級頁面才出現)   【分頁標題】     [🪙 1,250 金幣] [⚙️] |
+-------------------------------------------------------------+
|                                                             |
| 內容滾動區 (Main Content Area - SPA 瞬間切換，保持狀態):      |
|                                                             |
| 【Tab 1: 訓練室 (Home)】                                     |
|  ┌────────────────────────────────────────────────────────┐ |
|  │ 👾 局部像素遊戲小島 (Embedded Pixel Canvas Widget)         │ |
|  │    (小人自主巡邏/跑步機/深蹲/摸狗/情境氣泡/家具佈局)     │ |
|  └────────────────────────────────────────────────────────┘ |
|  • 今日任務卡片 (Daily Quests)                              |
|  • 連擊火焰 🔥 7 天 (Streak Card)                            |
|                                                             |
| 【Tab 2: 運動與課表 (Workout)】                              |
|  • 課表模板庫 (推/拉/腿)、秒表計時器、3 秒極速補登 (Web DOM) |
|                                                             |
| 【Tab 3: 社群廣場 (Plaza)】                                  |
|  • 拍立得動態瀑布流 (純像素卡片)、好友串門、Meme 拍貼按鈕     |
|                                                             |
| 【Tab 4: 本機數據 (Analytics)】                              |
|  • 100% 本機 IndexedDB 體重/體脂/睡眠/TDEE 趨勢曲線圖 (DOM)  |
|                                                             |
+-------------------------------------------------------------+
| 📱 底部固定導覽列 (Bottom Navigation Bar)                    |
|   [ 🏠 訓練室 ]    [ 🏋️ 運動打卡 ]    [ 🌐 廣場 ]    [ 📊 數據 ]  |
+-------------------------------------------------------------+
```

---

## 3. 架構實施要點 (Implementation Highlights)

1. **SPA 毫秒級無感切換 (No Full-Page Reload / Zero White Flash)**：
   - 底部 4 個主 Tab 切換採客戶端單頁路由，換頁零 Loading、零白屏跳頁。
   - 僅在非同步載入社群新動態或圖片時，使用局部骨架屏 (Skeleton UI)。
2. **全域狀態維持 (Tab State Preservation / Keep-Alive)**：
   - 核心狀態（運動秒表計時、正在輸入的訓練組數、錢幣餘額）提升至全域 Zustand 狀態機。
   - 使用者在「運動打卡 Tab」計時時切換至其他 Tab 查看數據，背景計時器持續跳動，狀態絕對不遺失。
3. **遊戲引擎智慧休眠 (Canvas Resource Lifecycle)**：
   - 當使用者離開「Tab 1 訓練室」時，嵌入式 PixiJS 畫布自動暫停 `ticker` 渲染，CPU/GPU 佔用歸零，徹底解決手機發燙與耗電問題。
4. **設計語言統一 (Neo-Retro 現代極簡復古風)**：
   - App 外殼底色採用沉浸式極黑 (`#0f111a`)，搭配精緻像素風格圖標與微光暈邊框，確保 Web DOM 與像素小人畫布在視覺上高度和諧統一。

---

## 4. 效益評估 (Consequences)

### 正面效益 (Positive)
- **開發效率提升 3~5 倍**：90% 的功能頁面直接以 React + Tailwind 現代元件堆疊。
- **手機續航大幅延長**：非遊戲頁面完全不耗費 GPU。
- **使用者體驗親切直覺**：符合大眾對手機 App 的普遍認知與操作慣性。

### 需防禦之潛在風險 (Risks & Mitigations)
- **避免廉價套殼網頁感**：嚴禁整頁跳轉重新 Loading；確保觸控點擊反饋時間小於 50ms。
